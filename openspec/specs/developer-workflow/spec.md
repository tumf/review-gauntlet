### Requirement: Local CLI install SHALL be available through Make

The repository SHALL provide a `make install` workflow that installs the local package as a uv tool and exposes the canonical `review-gauntlet` command. The install workflow SHALL NOT introduce or document the typo command name `review-guantlet`.

#### Scenario: Make install installs the canonical CLI

**Given**: a developer is in the repository root with `uv` available
**When**: they run `make install`
**Then**: the Make target invokes `uv tool install .`
**And**: the installed executable is the canonical `review-gauntlet` command declared by package metadata
**And**: no `review-guantlet` alias is added

#### Scenario: Installed CLI help is documented

**Given**: a developer reads the repository README
**When**: they follow the local CLI install guidance
**Then**: the guidance tells them to run `make install`
**And**: the guidance verifies the installed command with `review-gauntlet --help`
**And**: the guidance does not instruct them to use `review-guantlet`

### Requirement: CLI shell completion SHALL be generated by the canonical command

The `review-gauntlet` CLI SHALL provide a top-level `completion` command that emits shell completion scripts for supported interactive shells. Completion generation SHALL use the canonical `review-gauntlet` command name and SHALL NOT require a repository root, an active review session, or access to `.review-gauntlet` state.

#### Scenario: Bash completion script is generated without repository state

**Given**: an installed or development invocation of the `review-gauntlet` CLI
**When**: the developer runs `review-gauntlet completion bash`
**Then**: stdout contains a non-empty bash completion script for the canonical `review-gauntlet` command
**And**: the command exits `0`
**And**: no repository root validation or review-session state access is required

#### Scenario: Zsh completion script is generated without repository state

**Given**: an installed or development invocation of the `review-gauntlet` CLI
**When**: the developer runs `review-gauntlet completion zsh`
**Then**: stdout contains a non-empty zsh completion script for the canonical `review-gauntlet` command
**And**: the command exits `0`
**And**: no repository root validation or review-session state access is required

#### Scenario: Fish completion script is generated without repository state

**Given**: an installed or development invocation of the `review-gauntlet` CLI
**When**: the developer runs `review-gauntlet completion fish`
**Then**: stdout contains a non-empty fish completion script for the canonical `review-gauntlet` command
**And**: the command exits `0`
**And**: no repository root validation or review-session state access is required

#### Scenario: Completion includes current commands and options

**Given**: the CLI exposes review-gauntlet commands and subcommand options through its parser
**When**: the developer generates a supported shell completion script
**Then**: the script includes completions for the current top-level commands
**And**: the script includes completions for parser-visible subcommand options
**And**: completion metadata is not maintained through an unrelated duplicate command list that can silently drift from the parser

#### Scenario: Unsupported shell is rejected

**Given**: an installed or development invocation of the `review-gauntlet` CLI
**When**: the developer runs `review-gauntlet completion powershell`
**Then**: the command fails with the existing CLI usage-error behavior
**And**: no partial or dummy completion script is printed

### Requirement: Local CLI documentation SHALL include shell completion setup

Repository documentation SHALL explain how developers enable shell completions for supported shells using the installed canonical `review-gauntlet` command. Documentation SHALL NOT introduce or document the typo command name `review-guantlet`.

#### Scenario: README documents shell completion setup

**Given**: a developer reads the repository README after installing the CLI
**When**: they follow the shell completion guidance
**Then**: the guidance shows how to generate or install bash, zsh, and fish completions using `review-gauntlet completion <shell>`
**And**: the guidance does not instruct them to use `review-guantlet`
